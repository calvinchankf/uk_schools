# Development Guide

## Quick Start

The production site is fully static — no backend is needed. To run locally:

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:3000**.

If you have modified the raw government data and need to regenerate the processed JSON files, see [Data Processing](#data-processing) below.

## Data Processing

Run these scripts once (or whenever the source data changes). All scripts live in `scripts/` and read from `data_2024-2025/`.

### Prerequisites

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r scripts/requirements.txt
```

### Steps

```bash
# 1a. Geocode primary school postcodes (~4 min, ~16k schools)
python3 scripts/geocode_schools.py

# 1b. Geocode secondary school postcodes (~30 sec, incremental)
python3 scripts/geocode_secondary.py

# 2a. Build primary schools JSON with KS2 performance scores
python3 scripts/prepare_school_data.py

# 2b. Build secondary schools JSON with KS4 performance scores
python3 scripts/prepare_secondary_data.py

# 3. Validate geocoding success and score distribution
python3 scripts/validate_data.py

# 4. Generate place name → coordinates lookup for autocomplete
python3 scripts/gen_places.py

# 5. Copy into frontend
cp data_processed/schools_with_performance.json frontend/public/data/schools.json
cp data_processed/secondary_schools.json frontend/public/data/secondary.json
# places.json is written directly to frontend/public/data/ by gen_places.py
```

**Expected output:**
- `data_processed/schools_with_performance.json` — 16,403 primary schools
- `data_processed/secondary_schools.json` — 4,055 secondary schools
- `frontend/public/data/places.json` — 1,393 places (towns + boroughs), ~70 KB

### How `gen_places.py` works

Joins both school JSON files (lat/lon) with `england_school_information.csv` (TOWN and LANAME columns). Groups schools by normalised place name, computes the centroid lat/lon for each group, and outputs a sorted array. Town names take priority over borough names when both exist for the same key.

## Performance Score Calculation

All schools are ranked on a composite 0–100 score. Weights differ by phase.

### Primary — KS2

| Metric | Weight | Description |
|---|---|---|
| PTRWM_EXP | 40% | % at expected standard in reading, writing & maths |
| PTRWM_HIGH | 20% | % at high standard |
| READ_AVERAGE | 15% | Average reading scaled score (normalised from 80–120) |
| MAT_AVERAGE | 15% | Average maths scaled score (normalised from 80–120) |
| GPS_AVERAGE | 10% | Average GPS scaled score (normalised from 80–120) |

Minimum 3 valid metrics required.

### Secondary — KS4

| Metric | Weight | Description |
|---|---|---|
| PTL2BASICS_94 | 50% | % achieving grade 5+ in English and Maths (DfE "strong pass") |
| ATT8SCR | 35% | Attainment 8 score, normalised from observed range 0–87.2 |
| PTEBACC_94 | 15% | % achieving grade 4+ across all EBacc subjects |

Minimum 2 valid metrics required.

## Search Architecture

`api.js` exposes three search entry points, all purely client-side:

| Function | Input | How it works |
|---|---|---|
| `searchByPostcode` | UK postcode string | Geocodes via postcodes.io, then `searchNearbySchools` |
| `searchByPlaceName` | Place name string | Exact-match lookup in `places.json`, then `searchNearbySchools` |
| `searchNearbySchools` | lat, lon | Haversine filter over the in-memory schools array |

`App.jsx` routes the search bar input using a postcode regex (`/^[A-Z]{1,2}\d/i`): matches go to `searchByPostcode`, anything else goes to `searchByPlaceName`.

`getPlaceSuggestions(query)` filters `places.json` with a case-insensitive `startsWith` match and returns up to 8 results for the autocomplete dropdown.

## Frontend

### Running in development

```bash
cd frontend

npm run build    # production build → ../docs/

```

### Components

| Component | Responsibility |
|---|---|
| `App.jsx` | State, search routing, phase toggle, resize handle |

| `SearchBar.jsx` | Text input, postcode/place detection, autocomplete dropdown |
| `FilterPanel.jsx` | Radius selector |

### Responsive layout

On screens ≤ 768 px the layout switches from the desktop side-by-side view to a stacked mobile view:

- **Header**: compact single row (subtitle hidden)
- **Search bar**: full-width below the header (the map overlay is hidden)
- **Map**: 45 vh, shown first
- **Results list**: fills remaining height, scrollable, shown below the map

## Deployment (GitHub Pages)

The Vite build outputs to `../docs/` (configured in `vite.config.js`). GitHub Pages serves from the `docs/` folder on the `main` branch.

```bash
cd frontend
npm run build       # writes to ../docs/
git add ../docs
git commit -m "rebuild"
git push
```

The base URL is `/uk_schools/` (set in `vite.config.js`), matching `https://calvinchankf.com/uk_schools/`.

## Troubleshooting

**No schools appearing**
- Check browser console for errors
- Verify `frontend/public/data/schools.json` and `secondary.json` exist

**Place name not found**
- Re-run `python3 scripts/gen_places.py` to regenerate `places.json`
- The place must have at least one school in the dataset

**Geocoding fails during data processing**
- Check internet connection; postcodes.io may throttle — wait and retry
- ~1% failure rate is expected

**Frontend won't start**
- Node.js 18+ required
- Run `npm install` in `frontend/`
- Check port 3000 is free: `lsof -i :3000`
